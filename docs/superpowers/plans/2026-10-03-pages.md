# Pages (build 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the two-page NEXUS prototype into a worldwide storefront where every link resolves: collection and search pages with filters, compare, editable My setup, guides, account, orders, international checkout and confirmation, all persisted in the browser.

**Architecture:** A typed hash router (`routes.ts`) with the zustand store's `route` as the source of truth; a pure catalogue query engine (`catalog.ts`) that every page, rail and menu item reads through declared collections; shipping, tax and address rules per destination in `shipping.ts` and `validate.ts`; orders as stored snapshots whose status is a pure function of time. Pages are one component each under `src/pages/`.

**Tech Stack:** Vite 5, React 18, TypeScript strict, Tailwind 4, zustand 5 (+ `persist`), framer-motion, lucide-react, vitest for unit tests, Playwright (python) for screenshots and the link crawl.

**Spec:** `docs/superpowers/specs/2026-10-03-pages-design.md` (pages, worldwide) and `docs/superpowers/specs/2026-10-02-real-catalogue-design.md` (catalogue rules).

## Global Constraints

- Test Bench design system: paper/sheet/mat/ink/rule tokens, signal orange for fills only, 2 px controls, no shadows, no middle dots, no arrows, sentence case (see `src/styles/globals.css`).
- Published page is static: no server, no fetch to third parties, the CJ key never enters `src/`.
- Prices are AUD base, GST inclusive; `fmt()` converts for display; tax follows the delivery country.
- Every nav, mega-menu and footer item must resolve to a route that is not `not-found`, and a collection must return at least one product.
- Ratings only where value and count were verified; no invented reviews; copy says when something is a prototype ("No payment is taken in this prototype").
- `history.replaceState` and `localStorage` are wrapped in try/catch; the page renders with neither.
- Commits end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>` and `Claude-Session: https://claude.ai/code/session_01Jcv4PLvn3Huc3CBEYbWhbs`.

## Review Focus

1. A hash with a malformed filter string (`#/c/cinema?f=price:abc;route:`) must render the collection with the bad keys ignored, not a blank page. (Task 2 test `ignores malformed filter pairs`.)
2. A cart with both a Sydney and a China-origin line shipped to the UK must produce two shipments with different ETAs and costs, and the tax line must say VAT 20 % added. (Task 9 test `splits by origin for a UK address`.)
3. Checkout with the AU postcode 3000 and state NSW must refuse to continue with a field error, not place the order. (Task 8 test `rejects an AU postcode in the wrong state`.)
4. Returning after the browser cleared storage must show an empty cart and signed-out account without throwing; a blocked `localStorage` must still render. (Task 5 test `persist survives a throwing storage`.)
5. A collection page whose "Works with my setup" toggle leaves zero products must show the zero-results state with suggestions, and turning the toggle off must restore results. (Task 6 Playwright scenario `collection-zero`.)

  export type Sort = 'trending' | 'price-asc' | 'price-desc' | 'rating' | 'newest'
  export type Platform = 'ios' | 'android' | 'homekit' | 'google' | 'alexa' | 'matter' | 'thread'

  export type Route =
    | { name: 'home' } | { name: 'collection'; slug: string; filters: Filters; sort?: Sort }
    | { name: 'search'; q: string; filters: Filters; sort?: Sort } | { name: 'product'; id: string }

- Semantics pinned here: `platform` 'ios'/'android' match `facts.app`; the rest match `facts.home` or `facts.hubs`. `price: [min, max]` keeps `min <= price < max` (last band `max = Infinity`). `text` is lower-cased and split on non-alphanumerics; every token must be a prefix of some word in the haystack (name, brand, category, tagline, all spec values), so `ring` matches "RingConn" and "Ring 5" but not "charging". `setupItem` resolves the gear id against the catalogue's default gear (`DEFAULT_GEAR`, Task 7; `gear` until then), not the shopper's edited setup, so "Works with iPhone" means the same for everyone. `worksWithSetup` uses the `setup` argument.
