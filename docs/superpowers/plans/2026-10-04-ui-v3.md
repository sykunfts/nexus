# UI v3 (paper and ink, pushed) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Recompose the shop's home and product pages to match the approved v3 boards (bigger display type, offset hero on a bench slab, big mono numbers, one bento and one ledger, moderate motion) with the palette, fonts, routes and copy voice unchanged.

**Architecture:** Tokens and small shared pieces first (`globals.css`, `ui.tsx`, `Header`, `Footer`), then pure helpers with their data (`text.ts`, `bench.ts`, `Callouts`), then the home page as seven section components composed by `Home.tsx`, then the product page, then screenshots. Every section reads the existing data and store; no new state.

**Tech Stack:** Vite 5, React 18, TypeScript strict, Tailwind 4 (`@theme`, `@utility`), framer-motion, zustand, vitest + Testing Library (jsdom), Playwright (`shot.py`).

**Spec:** `docs/superpowers/specs/2026-10-04-ui-v3-design.md`

## Global Constraints

- Colour tokens, `--font-sans` (Bricolage Grotesque) and `--font-mono` (Martian Mono) are unchanged; `--radius-ctl: 2px` is the only radius.
- Routes, nav labels, slugs, anchor ids, the `data-name` attribute on `ProductImage`, and all copy not named in the spec are unchanged.
- No em dash (`—`) or en dash (`–`) in any UI string the tasks touch; hyphen for ranges. Catalogue data files are not edited.
- Nothing under `office/`, `radar/`, `data/`, `.github/` changes.
- Every clickable thing is a `button` or `a`; icon-only controls keep `aria-label`; status squares are `aria-hidden` beside text.
- Mount reveals only through framer-motion with `useReducedMotion()`; no scroll listeners, no marquee.
- Test command for the suite: `npx vitest run` (261 tests green before Task 1). Typecheck: `npm run typecheck`. Build: `npm run build`.
- Commits on branch `ui-v3`, one per task as the commit steps say.

## Review Focus

1. A shopper with every gear item toggled off opens the home: the setup panel shows "Add your phone, hub and plug once. Every product page then checks itself." and a "Set up in two minutes" button, never "these three" with no chips. (Task 6, `home.setup.test.tsx`)
2. A product whose specs have no Size row (most of the catalogue) renders no callout chips and no empty orange boxes; a Size row with a different unit ("in") still produces chips with that unit. (Task 3, `Callouts.test.tsx`)
3. With the office enabled, a Sydney-ledger product that is not sellable shows the compact stock-alert control instead of an Add button, and Add on a sellable one adds exactly one line. (Task 6, `home.shelf.test.tsx`)
4. A product with no `compareAt` shows no RRP text (not "RRP undefined"); a product with no bench rows renders no "Claimed, then measured" section at all. (Task 8, `product-v3.test.tsx`)
5. The bento is built from `MOVERS`, which comes from real trend data when `TRENDS_GENERATED_AT` is set; whichever four ids it yields, the section renders exactly four product links and every one opens a product that exists. (Task 7, `home.test.tsx`)
